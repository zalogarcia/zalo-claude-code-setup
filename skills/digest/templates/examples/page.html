How a Black Umbrella trial signup flows today

7 steps, 1 open gap. The signup reaches GHL and the bell. A finished onboarding reaches nothing in GHL.

    The page posts the form on the server to POST /functions/v1/onboarding-api.

  3. The session lives in the Black Umbrella agency. It copies the template (row eeee5555) when it is made.

    So a template change reaches new sessions only.

  4. The client answers the questions, then submits.

    Since 2 Oct, the "Book kickoff call" button on the thank-you screen opens the Tech Support calendar (new sessions only).

  5. created→started: first answer→completed: submit

    The cron job onboarding-webhook-dispatch sends them every minute. The first proof landed 49.2 s after the session was made.

    Each session sends "created" once, ever. The target is GHL inbound webhook trigger bbbb2222.

  6. A database trigger fires when the client starts or submits. It uses the same rule as the webhook, so the bell and the webhook never disagree.

    Only the agency owner gets it, once per session per event. No push and no email. Live since 2 Oct (PR #166).

  7. "Trial Reminders Black Umbrella DFY" aaaa1111, v7, published 2 Oct at 16:08 UTC.

    GHL inbound webhook triggers have no filter, so every event enters. The If/Else "Trial created only" passes onboarding.created.

    "started" and "completed" go to END. The workflow has no reminder waits yet.

How to close the gap (your call)
  1. Build the "Onboarding Submitted" workflow in GHL: a trigger plus steps.
  2. Point the Operator Base Submitted URL at the new trigger.
  3. Put the "stop the reminders" path there, once the trial workflow has reminder waits.
